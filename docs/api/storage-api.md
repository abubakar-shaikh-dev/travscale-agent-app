# Travscale API — Storage

Reference for the frontend agent. Covers every endpoint under `/storage`. See
[agency-api.md](./agency-api.md) for `/agency` and `/agency/me/locations`.

- **Base URL (dev):** `http://localhost:8000`
- **Content type:** `application/json` for every request and response below, **except**
  step 2 of the upload flow, which is a raw byte `PUT` straight to the bucket.
- **All timestamps:** ISO 8601 UTC strings, e.g. `"2026-10-04T05:30:50.123Z"`.
- **Rate limit:** 100 requests per minute per IP, shared across the whole API. A breach
  returns `429 RATE_LIMIT_EXCEEDED`.

| Endpoint                                           | Method   | Purpose                                 |
| -------------------------------------------------- | -------- | --------------------------------------- |
| [`/storage/upload-url`](#31-request-an-upload-url) | `POST`   | get a presigned `PUT` url               |
| [`/storage/confirm`](#32-confirm-the-upload)       | `POST`   | verify the bytes landed, unlock the key |
| [`/storage/url`](#33-get-a-signed-read-url)        | `GET`    | get a presigned `GET` url               |
| [`/storage`](#34-delete-a-file)                    | `DELETE` | remove the object and the record        |

---

## 1. Authentication

Every endpoint in this document requires an access token.

```
Authorization: Bearer <access_token>
```

Get it from `POST /auth/login`. The token lives at `data.access_token` in the response
envelope. It expires in **15 minutes**; refresh it with `POST /auth/refresh-token` using
`data.refresh_token` from login. A missing or invalid token returns:

| Status | `error.code`         | `message`                             |
| ------ | -------------------- | ------------------------------------- |
| 401    | `UNAUTHORIZED`       | Missing or invalid Bearer token       |
| 403    | `EMAIL_NOT_VERIFIED` | Verify your email address to continue |
| 403    | `ACCOUNT_SUSPENDED`  | This account has been suspended       |

`EMAIL_NOT_VERIFIED` means the account is still on the OTP step. The token from
`POST /auth/login` is valid, but it only reaches `/auth/verify-otp` and
`/auth/resend-otp` until the emailed code is submitted. `ACCOUNT_SUSPENDED` means
the account is `SUSPENDED` or `DEACTIVATED` and no endpoint will accept it.

The token identifies the **user**, never the agency. There is no `agency_id` parameter
anywhere in this document — every route operates on _the agency of the authenticated
user_, resolved server-side. A key or `upload_id` belonging to another agency is
indistinguishable from a missing one: both return `404 STORAGE_UPLOAD_NOT_FOUND`.

## 2. Response envelopes

Never read the payload directly. It is always nested under `data`.

### Success

```json
{
  "success": true,
  "message": "Presigned upload url created successfully",
  "data": {},
  "meta": {
    "timestamp": "2026-10-04T05:30:50.123Z",
    "request_id": "req-8fA2"
  }
}
```

### Error

```json
{
  "success": false,
  "message": "Storage upload not found",
  "error": {
    "code": "STORAGE_UPLOAD_NOT_FOUND",
    "details": null
  },
  "meta": {
    "timestamp": "2026-10-04T05:31:02.004Z",
    "request_id": "req-9Bc3",
    "path": "/storage/url"
  }
}
```

- `message` is human readable, show it directly.
- `error.code` is the stable machine value, branch on it.
- `error.details` is `null` for business errors. On a `400` validation failure it is an
  array of `{ "field": "body.entity_id", "message": "..." }` — use it for inline field
  errors.
- `error.details[].field` is a dot path, e.g. `body.entity_id` or `querystring.key`.

There is **no list endpoint** in this module, so no `pagination` envelope appears anywhere
below.

## 3. Storage API

Base path `/storage`. Every route needs the bearer token **and an existing agency** —
otherwise `404 AGENCY_NOT_FOUND`. The agency step of onboarding comes first, which is why
a logo is never uploaded before the agency exists. See
[onboarding-api.md](./onboarding-api.md).

Files live in a **private** bucket. The browser never sees bucket credentials. The backend
hands out short-lived signed URLs and the browser talks to the bucket directly. Object keys
are generated by the backend — a client cannot supply a path.

### 3.1 Purposes

`purpose` decides the folder, the accepted media types and the size ceiling.

| `purpose`              | `entity_id`         | Accepted `content_type`                                    | Max size             | Key folder (under `agencies/{agency_id}/`) |
| ---------------------- | ------------------- | ---------------------------------------------------------- | -------------------- | ------------------------------------------ |
| `agency_logo`          | not needed          | `image/png`, `image/jpeg`, `image/webp`                    | 2 MB (2,097,152 B)   | `branding/logo/`                           |
| `customer_document`    | **required** (UUID) | `application/pdf`, `image/png`, `image/jpeg`, `image/webp` | 20 MB (20,971,520 B) | `customers/{entity_id}/documents/`         |
| `supplier_document`    | **required** (UUID) | `application/pdf`, `image/png`, `image/jpeg`, `image/webp` | 20 MB (20,971,520 B) | `suppliers/{entity_id}/documents/`         |
| `itinerary_attachment` | **required** (UUID) | `application/pdf`, `image/png`, `image/jpeg`, `image/webp` | 20 MB (20,971,520 B) | `itineraries/{entity_id}/attachments/`     |
| `invoice_pdf`          | **required** (UUID) | `application/pdf`                                          | 10 MB (10,485,760 B) | `invoices/{entity_id}/pdf/`                |

Notes:

- SVG is **not** accepted anywhere, it can carry scripts when rendered inline.
- `entity_id` is the id of the record the file belongs to (customer, supplier, itinerary,
  invoice), not the file id.
- Absolute ceiling for `expected_size` on any purpose: 100 MB (104,857,600 B).
- Only the extension of `filename` is used, the name itself is ignored.
- Signed url lifetimes are **600 s** for writes and **300 s** for reads. Always read the
  actual value from `expires_in`, the defaults are server-side configured.

### 3.2 The upload flow

```
1. POST /storage/upload-url      → get upload_id, key, upload_url
2. PUT  upload_url (bucket)      → browser uploads raw bytes, no bearer token
3. POST /storage/confirm         → backend verifies the object, returns the real size
4. PATCH /agency/me              → save the key on the record that owns the file
5. GET  /storage/url?key=...     → get a fresh signed url to display the file
```

Nothing is visible to the rest of the app until step 3 succeeds. Step 4 is a normal agency
update, e.g. `{ "logo_key": "<key from step 1>" }`, see
[agency-api.md](./agency-api.md#53-update-my-agency).

#### 3.2.1 Request an upload URL

```
POST /storage/upload-url
```

**Body**

| Field           | Type   | Required    | Rules                                                                       |
| --------------- | ------ | ----------- | --------------------------------------------------------------------------- |
| `filename`      | string | yes         | 1–255 chars, no `/` or `\`                                                  |
| `content_type`  | string | yes         | valid media type, lowercased by the server, must be allowed for the purpose |
| `purpose`       | enum   | yes         | see [purposes](#31-purposes)                                                |
| `entity_id`     | string | conditional | UUID, required for every purpose except `agency_logo`                       |
| `expected_size` | number | no          | positive integer bytes, ≤ purpose ceiling and ≤ 100 MB                      |

```json
{
  "filename": "logo.png",
  "content_type": "image/png",
  "purpose": "agency_logo",
  "expected_size": 148213
}
```

`content_type` is matched literally against the allow list, so derive it from `File.type`
and fall back to a per-extension map when the browser leaves it empty.

**Response** — `201`

```json
{
  "success": true,
  "message": "Presigned upload url created successfully",
  "data": {
    "upload_id": "3e5f9c6d-b032-4b7c-8d9e-0f1220198b0f5",
    "key": "agencies/0198b0f2-.../branding/logo/3e5f9c6d-b032-4b7c-8d9e-0f1220198b0f5.png",
    "upload_url": "https://bucket.s3.amazonaws.com/...X-Amz-Signature=...",
    "expires_in": 600
  },
  "meta": { "timestamp": "2026-10-04T05:30:50.123Z", "request_id": "req-6" }
}
```

| Field        | Notes                                                             |
| ------------ | ----------------------------------------------------------------- |
| `upload_id`  | Use for confirm.                                                  |
| `key`        | **Store this on the owning record.** Not a URL.                   |
| `upload_url` | Single-use, expires in `expires_in` seconds (server default 600). |
| `expires_in` | Read it from the response, do not hardcode 600.                   |

This call only writes metadata and signs a url — no bytes are sent and no object exists
yet. Nothing is visible to the rest of the app until step 3 succeeds.

**Errors**

| Status | `error.code`                       | Cause                                                                          |
| ------ | ---------------------------------- | ------------------------------------------------------------------------------ |
| 400    | `VALIDATION_ERROR`                 | bad field, or missing `entity_id` for an entity scoped purpose                 |
| 400    | `STORAGE_CONTENT_TYPE_NOT_ALLOWED` | media type not in the purpose's allow list; `message` lists the accepted types |
| 400    | `STORAGE_FILE_TOO_LARGE`           | `expected_size` above the purpose ceiling; `message` states the limit          |
| 401    | `UNAUTHORIZED`                     | missing/expired token                                                          |
| 404    | `AGENCY_NOT_FOUND`                 | the user has no agency                                                         |

#### 3.2.2 Upload the bytes straight to the bucket

```
PUT <upload_url>
Content-Type: <the exact content_type sent in step 1>
Body: <raw file bytes>
```

- **No** `Authorization` header and no cookies — the signature in the url is the credential.
- The `Content-Type` header must match step 1 byte for byte, or the upload is rejected.
- Send the file as-is. Do not wrap it in `multipart/form-data`; the signed url covers a
  single `PUT` of the object body.
- Success is any `2xx` (S3 and R2 return `200`). A `403` means the url expired or the
  headers do not match — request a new one from step 1.
- This request goes to the **bucket**, not to this API. The API's own CORS config does not
  apply here — the bucket needs its own CORS rule allowing your origin, the `PUT` method
  and the `Content-Type` header, or the browser will block the call.

```ts
await fetch(upload_url, {
  method: "PUT",
  headers: { "Content-Type": content_type },
  body: file,
});
```

#### 3.2.3 Confirm the upload

```
POST /storage/confirm
```

Must be called before `expires_at`, which is `expires_in` seconds after step 1. The backend
reads the object back from the bucket, verifies the content type and the byte count, then
marks the upload usable. On a mismatch the upload is permanently marked `FAILED` — you must
start again at step 1 with a new `upload_id`.

**Body**

| Field       | Type          | Required |
| ----------- | ------------- | -------- |
| `upload_id` | string (UUID) | yes      |

```json
{ "upload_id": "3e5f9c6d-b032-4b7c-8d9e-0f1220198b0f5" }
```

**Response** — `200`

```json
{
  "success": true,
  "message": "Upload confirmed successfully",
  "data": {
    "upload_id": "3e5f9c6d-b032-4b7c-8d9e-0f1220198b0f5",
    "key": "agencies/0198b0f2-.../branding/logo/3e5f9c6d-b032-4b7c-8d9e-0f1220198b0f5.png",
    "content_type": "image/png",
    "size": 148213,
    "confirmed_at": "2026-10-04T05:31:12.480Z"
  },
  "meta": { "timestamp": "2026-10-04T05:31:12.480Z", "request_id": "req-7" }
}
```

`size` is the byte count read back from the bucket, not what you declared.

**Errors**

| Status | `error.code`                       | Cause                                      | What to do                                       |
| ------ | ---------------------------------- | ------------------------------------------ | ------------------------------------------------ |
| 400    | `VALIDATION_ERROR`                 | `upload_id` is not a UUID                  | fix the request                                  |
| 400    | `STORAGE_CONTENT_TYPE_MISMATCH`    | the `Content-Type` sent in step 2 differed | restart at step 1                                |
| 400    | `STORAGE_SIZE_MISMATCH`            | uploaded bytes ≠ `expected_size`           | restart at step 1, fix `expected_size`           |
| 401    | `UNAUTHORIZED`                     | missing/expired token                      | re-auth, retry                                   |
| 404    | `AGENCY_NOT_FOUND`                 | the user has no agency                     | —                                                |
| 404    | `STORAGE_UPLOAD_NOT_FOUND`         | unknown `upload_id` for this agency        | start at step 1                                  |
| 404    | `STORAGE_OBJECT_NOT_FOUND`         | step 2 never succeeded                     | redo step 2 with a new url, or restart at step 1 |
| 409    | `STORAGE_UPLOAD_ALREADY_CONFIRMED` | already confirmed                          | it is fine, continue to step 4                   |
| 410    | `STORAGE_UPLOAD_EXPIRED`           | `upload_id` is too old                     | restart at step 1                                |

### 3.3 Get a signed read url

```
GET /storage/url?key=...&disposition=inline
```

Only a **confirmed** upload is served. Nothing else in the app can see a `PENDING` or
`FAILED` file.

**Query**

| Param         | Type                     | Required | Default  | Notes                                                           |
| ------------- | ------------------------ | -------- | -------- | --------------------------------------------------------------- |
| `key`         | string                   | yes      | —        | The object key, read from the record that owns the file         |
| `disposition` | `inline` \| `attachment` | no       | `inline` | `inline` renders in the browser, `attachment` forces a download |

**Response** — `200`

```json
{
  "success": true,
  "message": "Signed url created successfully",
  "data": {
    "upload_id": "3e5f9c6d-b032-4b7c-8d9e-0f1220198b0f5",
    "key": "agencies/0198b0f2-.../branding/logo/3e5f9c6d-b032-4b7c-8d9e-0f1220198b0f5.png",
    "url": "https://bucket.s3.amazonaws.com/...X-Amz-Signature=...",
    "expires_in": 300
  },
  "meta": { "timestamp": "2026-10-04T05:32:00.000Z", "request_id": "req-8" }
}
```

**Errors**

| Status | `error.code`                   | Cause                                        |
| ------ | ------------------------------ | -------------------------------------------- |
| 400    | `VALIDATION_ERROR`             | `key` empty or contains `..`                 |
| 401    | `UNAUTHORIZED`                 | missing/expired token                        |
| 404    | `AGENCY_NOT_FOUND`             | the user has no agency                       |
| 404    | `STORAGE_UPLOAD_NOT_FOUND`     | no active upload for this key in this agency |
| 409    | `STORAGE_UPLOAD_NOT_CONFIRMED` | step 3 has not succeeded yet                 |

### 3.4 Delete a file

```
DELETE /storage?key=...
```

Deletes the object from the bucket and soft deletes the upload record. The key is then
unusable — `GET /storage/url` returns `404 STORAGE_UPLOAD_NOT_FOUND` forever, there is no
restore. Deleting a key that is not in the bucket still succeeds.

No status check runs here, so a `PENDING` or `FAILED` upload can be deleted too. `key` is
a query parameter, **not** a path parameter.

**Query**

| Param | Type   | Required | Notes                                                   |
| ----- | ------ | -------- | ------------------------------------------------------- |
| `key` | string | yes      | The object key, read from the record that owns the file |

**Response** — `200`

```json
{
  "success": true,
  "message": "File deleted successfully",
  "data": {
    "upload_id": "3e5f9c6d-b032-4b7c-8d9e-0f1220198b0f5",
    "key": "agencies/0198b0f2-.../branding/logo/3e5f9c6d-b032-4b7c-8d9e-0f1220198b0f5.png",
    "deleted": true
  },
  "meta": { "timestamp": "2026-10-04T05:33:00.000Z", "request_id": "req-9" }
}
```

**Errors** — `400 VALIDATION_ERROR`, `401 UNAUTHORIZED`, `404 AGENCY_NOT_FOUND`,
`404 STORAGE_UPLOAD_NOT_FOUND`.

### 3.5 Storage errors

Every `error.code` this module can return, in one place.

| Status | `error.code`                       | `message`                                                          |
| ------ | ---------------------------------- | ------------------------------------------------------------------ |
| 400    | `VALIDATION_ERROR`                 | Validation failed                                                  |
| 400    | `STORAGE_CONTENT_TYPE_NOT_ALLOWED` | dynamic — lists the accepted types                                 |
| 400    | `STORAGE_FILE_TOO_LARGE`           | dynamic — states the limit                                         |
| 400    | `STORAGE_CONTENT_TYPE_MISMATCH`    | Uploaded content type does not match the presigned upload url      |
| 400    | `STORAGE_SIZE_MISMATCH`            | Uploaded file size does not match the expected size                |
| 401    | `UNAUTHORIZED`                     | Missing or invalid Bearer token                                    |
| 404    | `AGENCY_NOT_FOUND`                 | Agency not found                                                   |
| 404    | `STORAGE_UPLOAD_NOT_FOUND`         | Storage upload not found                                           |
| 404    | `STORAGE_OBJECT_NOT_FOUND`         | No object was uploaded to the storage bucket                       |
| 409    | `STORAGE_UPLOAD_ALREADY_CONFIRMED` | This upload has already been confirmed                             |
| 409    | `STORAGE_UPLOAD_NOT_CONFIRMED`     | Upload is not confirmed yet, confirm it before requesting the file |
| 410    | `STORAGE_UPLOAD_EXPIRED`           | The upload url has expired, request a new one                      |
| 429    | `RATE_LIMIT_EXCEEDED`              | Rate limit exceeded. Try again in N                                |

## 4. Frontend integration notes

**Store keys, not urls.** A record such as `agency.logo_key` holds an object key like
`agencies/{id}/branding/logo/{uuid}.png`. To render the file you must call
`GET /storage/url?key=<key>` and use the returned `url`.

**Signed urls expire.** The default lifetime is 300 s for reads and 600 s for writes, and
both are configurable server-side. Always read `expires_in` from the response. Re-request a
read url when it is about to expire rather than caching it across sessions, and never
persist a signed url.

**Logo flow, end to end.**

```
user picks a file
  → client-side check: type in allow list, size ≤ 2 MB
  → POST /storage/upload-url   { filename, content_type: "image/png", purpose: "agency_logo", expected_size }
  → PUT upload_url             raw bytes, Content-Type: image/png
  → POST /storage/confirm      { upload_id }
  → PATCH /agency/me           { logo_key: key }
  → GET /storage/url?key=...   to display it
```

**Replacing a logo** repeats steps 1–4 with the new key, then delete the old file with
`DELETE /storage?key=<old key>`. Deleting first leaves a window with no logo.

**Deleting a logo** does not clear `agency.logo_key` — the backend has no endpoint to null
it out. Treat `logo_key` as possibly stale: if `GET /storage/url` returns
`404 STORAGE_UPLOAD_NOT_FOUND`, fall back to a placeholder avatar.

**Client-side validation.** The server rejects bad media types and oversized files at
upload-url time, but checking in the browser first avoids a pointless round trip.

**What is not persisted.** `filename` and `entity_id` are validated but not stored on the
upload record, so do not expect them back from any endpoint. Each object key is unique per
agency, and keys embed a fresh uuid, so re-uploading the same file always creates a new
object rather than overwriting.

**Suggested api-client surface.**

```ts
storageApi = {
  createUploadUrl: (body) => post("/storage/upload-url", body), // 201
  uploadToBucket: (upload_url, file, content_type) =>
    put(upload_url, file, { headers: { "Content-Type": content_type } }), // no auth
  confirm: (upload_id) => post("/storage/confirm", { upload_id }),
  signedUrl: (key, disposition = "inline") =>
    get("/storage/url", { query: { key, disposition } }),
  remove: (key) => del("/storage", { query: { key } }),
};
```
